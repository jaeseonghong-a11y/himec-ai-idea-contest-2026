**왕복 검증**은 수정된 도면에서 관계도를 다시 읽어 편집기의 최종 상태와 대조하는 것이다.

### 2-2. 안 되는 것, 확인하지 못한 것

- **AI가 아직 들어 있지 않다.** 전부 규칙 코드다. 회의 발화 해석, 대안 제시, 레이어 매핑 제안은 설계만 했다.
- **편집기의 마우스 조작을 직접 시험하지 못했다.** 계산과 화면 그리기만 검증했다.
- 설비·전기·소방은 가상이고 기준값은 가정이다.
- 덕트 경로 편집, 배관, 회로 연결 없음.
- 사선 벽, 좌우 반전 도면, 곡선 해치 미처리.
- 그리드 번호는 좌표순 자동 명명(도면의 실제 번호를 못 읽음).
- 추가·삭제·문창호 편집은 평면도 한 장에만 반영. 여러 도면 전파는 그리드 이동만.
- 폭을 추정한 문·창호 타입 5종은 사람 확인 필요.
- 최신 편집 시나리오 결과는 AutoCAD로 다시 열어 보지 않았다.

## 4. 권하는 다음 순서

1. **#17을 먼저 끝낸다.** 다른 팀원의 입력이 되는 조각이라 늦으면 팀 전체가 막힌다. 기존 합성 도면 생성기를 계약 형식에 맞춰 고치면 2~3시간 안에 첫 산출물(DXF 1장 + 사이드카 1개)을 공유할 수 있다.
2. **프로토타입을 팀장에게 알린다.** 범위가 겹치므로 임의로 저장소에 넣지 않고, 무엇을 만들었는지와 검증 결과를 이슈 댓글이나 PR 설명으로 공유해 팀장이 채택 범위를 정하게 한다. 관계도 편집기와 왕복 검증은 제안서의 "실현가능성" 근거로 쓸 수 있다.
3. **제안서에 쓸 화면을 합성 도면으로 다시 찍는다.** 실제 도면 화면은 제출물에 쓸 수 없다.
4. 그 다음에 LLM 연결(경고에 대한 대안 제시와 검증 순환).
