# 관계도 프로토타입 (묶음 D + 묶음 C + 묶음 A 최소)

HIMEC AI 아이디어 공모전 데모. 도면을 "형태"가 아니라 "관계"로 읽고, 관계도에서 변경을 넣으면 연결된 요소(기둥·스팬·치수)가 갱신되며, 그 변경이 회의 발화 추출과 같은 `changes.json` 형식으로 기록되어 실제 DXF 도면 세트 전체에 반영된다.

저장소 밖 실험 폴더다. 팀장이 Round 02를 배정하면 코드만 `prototype/` 아래로 옮겨 커밋한다. **`real sample/`, `real_dxf/`, `out/real/`은 실제 프로젝트 도면(사무소명·인허가 정보 포함)이므로 절대 공개 저장소에 올리지 않는다.** 제출용 캡처는 제목란을 잘라내거나 합성 도면으로 대체한다.

AutoCAD가 출력한 PDF에는 레이어 40개가 이름 그대로, 벡터 경로 3,404개가 레이어 소속과 함께, 치수 숫자가 실제 글자로 남는다(실측). 잃는 것은 블록·치수 객체·선종류(일점쇄선은 조각남)·객체 핸들이다.

복원 방법: 그리드 조각을 이어 붙이고, **그리드 간격(pt)과 치수 숫자(mm)를 대조해 축척을 추정**(1/100로 확인), 치수 숫자를 그 위치의 그리드 쌍에 연결하고, 그 숫자로 그리드 좌표를 보정(최대 2.8 mm)한다.

| 항목 | PDF에서 읽음 | 원본 DXF |
|---|---|---|
| 그리드 Y / X | 9 / 7 | 9 / 8 (원본의 250 mm 짧은 보조선 1개는 PDF에서 제외) |
| 그리드 간격 | 600, 1450, 1350, 5700, 2900, 2800 등 | 동일 |
| 기둥 | 7, 단면 7개 모두 동일 | 7 |
| 벽 / 보 | 27 / 7 | 27 / 7 |
| 치수(그리드 연결) | 30 | 30 |
| 창호 / 문 | 3 / 7 | 2 / 6 (군집 경계 차이) |

한계: 레이어가 없는 PDF, 스캔 PDF는 이 방식으로 읽지 못한다. 핸들이 없으므로 PDF에서 읽은 관계도로 원본 DWG를 직접 고치려면 좌표로 객체를 다시 찾아야 한다(띠 STRETCH는 좌표 기반이라 가능).

## D-0. 건물 전체 문·창호 일람표

```text
python graph/build_schedule.py              # 1~4층 평면도(A12~A15)에서 읽어 out/real/schedule.json, schedule.png 생성
python tools/opening_survey.py              # 층별 문·창호의 기호 폭과 벽체가 끊긴 폭 조사
```

- **호칭 치수**: 기호 크기가 아니라 콘크리트 벽체(COL)가 끊긴 폭을 잰다. 창호 기호 580 → 600, 880 → 900, 1180 → 1200, 1980 → 2000. 문 기호 690 → 800, 790 → 900, 2짝 1600 → 1800
- **타입 기준**: 종류, 짝 수, 호칭 치수, 기호 구성(객체 수 차이 3개 이하는 같은 타입)
- **원본 기억**: 타입마다 그 기호가 그려진 도면·객체·위치를 기억해, 다른 도면에 넣을 때 복사해 온다
- **가상 타입**: 도면에 없는 표준 크기(창호 1800·2400, 문 1000, 2짝 1500)는 '가상'으로 채운다. 복사할 기호가 없어 기본 기호로 그려진다
- **확인 필요(※)**: 벽체 개구부를 재지 못해 폭을 추정한 타입. 기호에 창호가 아닌 선이 섞였을 수 있다

실측(2026-09-29): 실제 창호 10종, 문 6종, 가상 4종. 문 띠 4개는 벽 길이에 맞춘 것이라 타입에서 제외. `schedule.png`에 타입별 실제 기호가 그려진다.

| 그리드 추가·삭제 | 그리드 선택 후 거리 입력. 요소가 놓인 그리드는 삭제 불가 | 교점 |

표시: 빨강 = 변경, 초록 = 새로 추가, 흐린 빨강 점선 = 삭제. 경고는 이번 편집으로 **새로 생긴 것만** 보여 준다.

### 도면 반영 (`propagate/apply_edits.py`)

적용 순서는 그리드 이동 → 삭제 → 기둥 단면 → 개구부 수정 → 추가이며, 실무의 캐드 조작을 따른다.

| 편집 | 도면에서 하는 일 |
|---|---|
| 그리드 이동 | 띠 STRETCH, 치수 재렌더, 기둥-벽선 동반 검사 |
| 문·창호 이동 | 개구부 객체를 옮기고 양쪽 문틀 주변의 벽 계열 선 끝을 함께 STRETCH |
| 문·창호 크기 변경 | **타입 교체.** 기존 기호를 지우고, 그 타입이 그려진 곳의 기호를 복사해 넣는다(벽 방향이 다르면 90도 회전, 안팎이 다르면 반전). 문틀 위치만 새 폭에 맞춰 옮긴다. 일람표에 새로 추가한 타입은 복사할 원본이 없어 기본 기호를 그린다. 기호를 늘이지 않으므로 창틀 상세가 깨지지 않는다 |
| 문·창호 추가 | 벽선을 폭만큼 잘라내고(폴리선은 분해) 실제 벽 두께를 찾아 문틀선을 그린 뒤, 선택한 타입의 기호를 복사해 넣음 |
| 문·창호 삭제 | 기호·문틀 삭제, 끊어진 벽선을 같은 오프셋끼리 다시 이음 |
| 기둥 추가·삭제·단면 | COL 사각 폴리선 생성·삭제·재작성 |
| 벽 추가·삭제 | 이중선 생성 / 구간의 벽선 잘라냄 |
| 보 추가·삭제 | 은선 레이어에 이중 점선 생성 / 은선 삭제. 기둥 사이 구조 추정 보는 그려진 선이 없어 관계도에만 반영 |
| 그리드 추가·삭제 | CEN 선 생성·삭제 |

- 타입의 원본 기호는 다른 편집보다 먼저 떠 두므로, 원본으로 쓴 문을 같은 편집에서 지워도 복사가 된다

검증 중 고친 것

- 문틀 주변을 늘일 때 모든 레이어를 옮겨 화장실 칸막이가 비스듬해짐 → 벽 계열 레이어로 제한
- 이 도면은 콘크리트 벽체를 COL 레이어에 그림 → 벽 계열에 COL 추가(기둥 사각형은 제외)
- 600 mm 떨어진 X1·X2가 같은 벽선을 각자 벽으로 읽어 관계도에 벽이 중복 → 벽선을 가장 가까운 그리드 한 곳에만 배정
- 문 위치를 경첩으로 읽어 폭의 절반만큼 어긋남 → 호가 차지한 범위의 중심으로, 문짝·문틀도 같은 문으로 묶음
- 문틀을 옮길 때 벽과 직각인 선의 한쪽 끝만 움직여 비스듬해짐 → 이동 방향과 나란한 선만 늘이고 나머지는 통째로 옮김

## E. 설비·전기·소방 (가상 배치)

이 도면 세트에는 설비·전기 도면이 없다. 건축 변경이 다른 분야로 번지는 것을 보이기 위해 **가상 일람표와 가상 배치**를 만들어 1층 평면 위에 얹었다. 실제 하이멕 표준이나 실제 설계가 아니며, 검사 기준값도 데모용 가정이다.

```text
python mep/mep_schedule.py                 # 가상 일람표 → out/real/mep_schedule.json, mep_schedule.png
python mep/make_layout.py                  # real_dxf/A12.dxf + 가상 배치 → real_dxf/A12M.dxf ('M' 도면은 생성물)
python graph/build_graph_real.py A12M      # 기구·덕트까지 읽은 관계도
python editor/build_editor.py real open    # 편집기 (전기·설비·소방 표시 켜고 끄기, + 기구)
```

## F. 맨땅에서 시작하는 새 프로젝트

기존 도면을 고치는 데 쓰던 관계도 모델을 계획 초기에 그대로 쓴다. 대지경계선만 있는 상태에서 그리드, 기둥, 벽, 보, 문·창호, 코어, 기구를 하나씩 얹고, 관계도에서 도면을 새로 그린다.

```text
python editor/build_editor.py blank NEW1 open    # 빈 편집기
node editor/test_new.js NEW1                     # 계산 검증 20개 + 예시 계획안의 변경 파일·기대값
python propagate/apply_edits.py NEW1 out/editor/changes_new.json out/editor/expected_new.json --quick   # 관계도 → 도면
```

| 요소 | 방법 | 비고 |
|---|---|---|
| 대지 | 가로×세로 입력 또는 꼭짓점 클릭 | 면적, 대지 밖 요소 경고 |
| 그리드 | 간격을 한 번에 입력 또는 클릭 | 그리드선은 대지를 덮도록 자동으로 뻗음. 치수열 자동 생성 |
| 기둥·벽·보·문·창호·기구 | 기존 편집기와 같음 | 문·창호 일람표는 과거 도면의 타입(기호 복사)과 표준 크기 가상 타입 |
| 승강기 | 인승별 크기 타입 | 8인승 1800×2000, 11인승 2000×2200, 15인승 2200×2500 (가정값) |
| 계단 | 폭 타입과 올라가는 방향 | 층고에서 단수·단높이·길이 자동 계산. 단높이 상한 180, 단너비 280 (가정값) |
| 개략 지표 | 대지면적, 건축면적(벽이 있는 범위의 사각형), 건폐율 | 개략값 |

도면 그리기는 새 기능이 아니라 기존의 "추가" 동작을 빈 도면에 차례로 적용하는 것이다. 읽기 쪽이 아는 레이어 이름(CEN, COL, WAL, WID, DOOR, HID, RXDIM)으로 그리므로 그린 도면을 다시 관계도로 읽을 수 있다.

### 실측 결과 (예시 계획안 NEW1)

대지 26×19 m, 그리드 4×3, 기둥 12, 외벽 10구간, 보 17구간, 문 1, 창호 5, 승강기 1, 계단 1, 기구 38.

- 계산 검증 20개, 화면 조작 시험 18개 통과(대지 점 찍기, 그리드 클릭, 코어 놓기·방향·뒤집기, 층고 변경 포함)
- **왕복 검증 29/29 일치**: 그린 도면에서 기둥 12, 벽 10, 문·창호 6, 기구 38을 다시 읽어 관계도와 대조
- 문과 창호는 과거 도면(A12, A13)의 기호가 복사되어 들어감

- **AutoCAD 2024 확인**(`python tools/verify_generated_autocad.py NEW1`): 그린 도면이 열리고, 치수 7개를 AutoCAD가 다시 계산한 값이 기대값과 모두 일치, 도면 검사(AUDIT) 오류 0건, AutoCAD의 PDF 출력 정상. 처음에는 다른 도면에서 가져온 레이어 2개의 출력 스타일 참조가 끊겨 오류 8건이 났고, 가져온 레이어의 참조를 기준 레이어 값으로 맞춰 해결했다

생성되는 치수는 **그리드 사이 치수열과 전체 치수**뿐이다. 개구부 위치 치수, 벽 두께, 기둥 크기, 코어 치수, 레벨은 없다. 선 굵기 구분, 선종류 축척, 치수 문자 크기 같은 도면 표현 규칙도 아직 없어 출력하면 모든 선이 같은 굵기로 나온다.

## changes.json 스키마 (1단계와 공용)

```json
{
  "id": "CR-001",
  "source": {"type": "graph_input", "text": "X6 move 500", "speaker": null, "time": "..."},
  "sheet": "A12", "target": "X6", "action": "move", "params": {"delta": 500.0},
  "confidence": 1.0, "status": "confirmed", "reviewer": "graph-operator", "reviewed_at": "...",
  "impacts": [
    {"element": "X6", "kind": "grid", "handles": ["8B41"], "delta": 500.0, "axis": "x"},
    {"element": "C@X6-Y2", "kind": "column", "handle": "8B42", "delta": 500.0, "axis": "x"},
    {"element": "DIM 8B54", "kind": "dimension", "handle": "8B54", "moved_grid": "X6", "old_coord": 21135, "delta": 500.0, "axis": "x"}

  "warnings": []

```

1단계(회의 발화)는 `source.type = "transcript"`, `confidence < 1`, `status = "proposed"`로 같은 형식을 만든다. 2단계는 `status = "confirmed"`인 항목만 반영한다.

## 알려진 한계

- 문·창호 일람표는 평면도의 기호에서 역으로 만든 것이다. 설계사무소가 따로 그린 창호 일람표 도면(재질·유리·개폐 방식)은 이 도면 세트에 없어 읽지 않았다.
- 폭을 추정한 타입(※)은 기호에 무관한 선이 섞였을 수 있어 사람이 확인해야 한다.
- PDF에서 읽은 관계도에는 객체 핸들이 없어 기호 복사를 쓸 수 없다(기본 기호로 그려짐).
- 문·창호 상세 중 인식하지 못한 레이어에 그려진 선은 타입 교체·삭제 뒤에도 남을 수 있다.
- 문 띠(접이문·쇼윈도)는 기호 복사 대상이 아니다. 타입 교체 시 기본 기호로 그린다.
- 벽선을 자르거나 이을 때 벽 폴리선을 선으로 분해한다. 모양은 같지만 객체 종류가 바뀐다.
- 요소 추가·삭제·개구부 편집은 한 도면(평면)에만 반영된다. 여러 도면 전파는 그리드 이동만 지원한다.
- 편집기의 마우스 끌기는 자동 검증하지 못했다(계산과 화면 그리기만 검증).
- 설비·전기·소방은 가상 배치이고 기준값은 가정이다. 실제 설비 도면을 읽는 규칙(레이어·블록 이름)은 그 도면을 받아야 정할 수 있다.
- 덕트는 직각 경로만 다루고, 경로를 편집기에서 고치는 기능은 없다(경고만 낸다). 배관·전선관·회로 연결은 없다.
- 구획은 기구를 넣을 때 정한 그리드 네 줄이다. 방(실) 단위가 아니어서 사선 벽 밖으로 나가는 기구를 걸러내지 못한다.
- 그리드 명칭은 좌표순 자동 명명이다. 도면의 실제 그리드 번호(문자)는 모델 공간에 없어 읽지 못했다.
- 띠 폭 ±700 mm는 데모용 값이다. 기둥 폭·벽 두께에 따라 조정해야 하고, 띠 안에 있는 무관한 객체(가구 블록 등)도 함께 움직인다. 이동 목록을 레이어별로 보고하므로 사람이 확인한다.
- 배면도(A20)처럼 좌우가 뒤집힌 도면은 정렬 오프셋만으로 대응했고 반전은 처리하지 않았다. 치수 지원이 0이므로 확인이 필요하다.
- 2·3층 평면도는 X6 위치에 구조 요소가 없어 도면 구성 확인이 필요하다.
- 곡선 경계 해치, 지시선(LEADER), 스플라인은 이동하지 않고 표시만 한다.
- 벽은 그리드 기반 관계도에서 아직 엣지로 잡히지 않는다(정합성 검사가 사후 확인).
- 스팬 경고 기준 7.5 m는 데모용 가정이다.
- AutoCAD COM 검증은 문서를 읽기 전용으로 열면 치수 조회가 거부되고, ezdxf가 재생성한 치수는 `entmod`로 다시 써야 AutoCAD가 실측값을 계산한다.
