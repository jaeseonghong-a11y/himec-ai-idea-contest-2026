## 작업 방식

- 한 번에 검증 가능한 작은 단위로 작업합니다. 사용자 시나리오와 완료 기준을 먼저 확인합니다.
- 외부 SDK/API 동작과 CAD 호환성은 실제 환경·공식 문서·샘플로 검증합니다. 추측을 확정 사실로 쓰지 않습니다.
- 순수 계산과 CAD host 의존 코드를 가능한 한 분리합니다.
- 코드 변경 후 [[여기에 실제 lint/build/test 명령]]을 실행합니다. 실제 AutoCAD에서 해야 할 검증은 별도로 기록합니다.
- 검사 실패는 원인을 고치고 다시 실행합니다. 테스트를 끄거나 오류를 숨겨 통과시키지 않습니다.
- 도면 수정은 취소·예외·Undo·저장 후 재열기와 함께 검증합니다. 테스트 도면은 복사본을 사용합니다.
- API 키·토큰·고객 도면·개인정보를 코드, 로그, 커밋에 남기지 않습니다.
- 커밋 메시지: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:` 중 적절한 말머리를 사용합니다.

## GitHub 팀 규칙

- `main`은 보호 브랜치입니다. 기능별 브랜치에서 push하고 PR을 열어 검토·CI 후 병합합니다.
- 다른 사람의 미커밋 변경을 reset/stash/checkout으로 없애지 않습니다. 병행 작업은 별도 worktree로 분리합니다.
- PR 병합은 사용자가 해당 PR의 병합을 요청했거나 팀의 명시된 권한 규칙 안에서만 수행합니다. 보호 규칙·승인을 우회하지 않습니다.
- 충돌 시 양쪽 의도를 분석하고 통합합니다. `ours`/`theirs` 전체 선택으로 무심코 덮지 않습니다.
- 병합과 제품 배포는 별도 단계입니다. 배포 방법은 [[배포 절차 문서/미정]]입니다.
