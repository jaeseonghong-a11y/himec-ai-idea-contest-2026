# 01. 새 프로젝트 시작하기

## 준비물

- Git, GitHub 계정과 팀원의 저장소 접근 권한
- VS Code 등 편집기와 사용할 AI 코딩 도구
- 플러그인을 시험할 AutoCAD 제품·버전·운영체제·라이선스
- 개인정보와 저작권을 확인한 테스트용 도면
- 선택: GitHub CLI(`gh`). 설치·인증: https://cli.github.com/manual/

## 1. 새 저장소

GitHub에서 저장소를 만들고 팀원은 각자 clone합니다.

```powershell
git clone https://github.com/OWNER/REPO.git
Set-Location REPO
git status --short
```

기존 저장소를 clone한 경우 `git init`을 다시 실행하지 않습니다. `OWNER/REPO`는 실제 값으로 바꿉니다.

## 2. 템플릿 복사

`templates/` 아래의 상대 경로를 새 저장소 루트에 복사합니다. `.gitignore.example`은 내용을 검토해 `.gitignore`로 이름을 바꿉니다. `ci-examples/`는 참고 자료이며, `.example` 파일은 그대로 두면 실행되지 않습니다.

```text
새 저장소/
├─ AGENTS.md
├─ CLAUDE.md
├─ CURRENT_STATE.md
├─ docs/
│  ├─ PROJECT_BRIEF.md
│  └─ DECISION_LOG.md
└─ .github/
   └─ PULL_REQUEST_TEMPLATE.md
```

`AGENTS.md`의 스택·검증 명령과 `PROJECT_BRIEF.md`의 범위·성공 기준을 채웁니다. 원본 시간표 프로젝트의 도메인 규칙은 복사하지 않습니다.

## 3. 첫날 결정

`04_AutoCAD_프로젝트_결정사항.md`의 질문을 팀과 확인합니다. 특히 지원 AutoCAD 제품/연도, 플러그인 방식, 동반 앱의 역할, 실제 CAD 테스트 환경을 결정해야 합니다. 결정하지 못한 것은 추정하지 말고 `미정`으로 남깁니다.

## 4. 검증과 main 보호

1. 실제로 실행되는 빌드·린트·테스트 명령을 정합니다.
2. 이를 GitHub Actions CI에 넣고 PR에서 성공하는지 확인합니다. `templates/ci-examples/ci-dotnet.yml.example`은 .NET을 선택했을 때의 **참고 예시**로, 이름을 바꾸고 수정하기 전에는 실행되지 않습니다.
3. 그다음 GitHub의 `main` 보호 규칙에서 PR, 리뷰, 필수 통과 검사를 설정합니다. 실제 CI 검사 이름을 확인한 후 등록합니다. 설정·계정 제한은 [공식 문서](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)를 확인합니다.
4. `main` 직접 push와 force push를 금지하는 팀 규칙을 공유합니다.

## 5. 첫 기능

`05_복붙_프롬프트.md`의 **0. 프로젝트 초기화**, **1. 첫 수직 기능**을 사용합니다. 첫 기능은 입력 → 처리 → CAD 결과 또는 화면 표시까지 얇게 연결하고, 실제 AutoCAD에서 로드·실행·취소·Undo를 시험합니다.

## 팀원에게 전달할 최소 안내

팀원은 `02_팀_GitHub_브랜치_PR_병합.md`의 **팀원 절차**대로 기능별 브랜치를 만들고 push한 뒤 PR URL을 보냅니다. push만 하면 리뷰·병합 대기열에 자동으로 올라오는 것은 아닙니다.
