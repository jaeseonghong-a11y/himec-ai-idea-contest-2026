# 03. 개발·검증·인수인계

## 매일의 작업 루프

1. 시작: `AGENTS.md`, `CURRENT_STATE.md`, `git status --short`, `git log --oneline -5`를 읽습니다. 문서와 코드가 다르면 코드를 조사합니다.
2. 범위 정리: 한 번에 검증할 수 있는 변경 단위와 완료 기준을 정합니다. 변경 파일 소유자가 겹치는지 확인합니다.
3. 구현: 먼저 가장 얇은 입력 → 처리 → 출력 흐름을 만듭니다. 외부 SDK 동작은 추측하지 않고 작은 실측으로 확인합니다.
4. 검증: 해당 프로젝트의 빠른 자동 검사 → CAD host 통합 검사 → 실제 사용자 경로 순서로 확인합니다.
5. 리뷰: diff를 읽고 예기치 않은 삭제, 디버그 코드, 비밀값, 설치·호환성 영향을 점검합니다.
6. 인수인계: `CURRENT_STATE.md`에 한 일, 변경 파일, 실제 실행한 명령, 통과/실패, 막힌 곳, 다음 한 가지 행동을 씁니다. 큰 작업이면 별도 작업 로그를 남깁니다.
7. 커밋·푸시·배포는 팀에서 정한 권한과 사용자의 구체적인 요청에 따라 진행합니다. 병합과 배포는 서로 다른 단계입니다.

## 품질 게이트를 실제 명령으로 채우기

스택이 확정되면 `AGENTS.md`에 **실행 가능한 한 줄 명령**으로 적습니다. 예를 들면 .NET 프로젝트는 `dotnet restore`, `dotnet build --no-restore`, `dotnet test --no-build`를 검토할 수 있습니다. 하지만 AutoCAD 참조 어셈블리·라이선스·운영체제에 따라 CI에서 빌드 가능한 범위가 다를 수 있으므로 실제로 통과시킨 뒤 필수 검사로 등록합니다.

| 단계 | 예시 검증 | 누가/어디서 |
|---|---|---|
| 정적 | 포맷, 린트, 타입·컴파일, 비밀값 검사 | 로컬 + CI |
| 순수 로직 | 도면 계산, 좌표·단위 변환, 입력 검증의 단위 테스트 | 로컬 + CI |
| CAD 통합 | 플러그인 로드, 명령 등록, 도면 수정, 예외·Undo | 실제 AutoCAD 환경 |
| 제품 경로 | 설치 → 첫 실행 → 정상 작업 → 저장 → 재실행 | 팀원이 수동 확인 |

스택이 정해지면 로컬 pre-commit 훅에도 빠른 검사와 비밀값 검사를 연결할 수 있습니다. 훅은 건너뛸 수 있으므로 CI에서 다시 검사해야 합니다.

자동 테스트가 통과해도 AutoCAD에서 로드되지 않으면 완료가 아닙니다. 반대로 AutoCAD 실기 테스트가 어렵다면 “미검증”을 명시하고 배포 기준을 따로 정합니다.

## 오류를 다루는 방법

증상을 재현 → 관련 입력·환경 기록 → 최근 변경 확인 → 원인 좁히기 → 수정 → 같은 재현으로 재검증합니다. 실패한 테스트를 끄거나 빈 결과를 정상으로 처리해서 통과시키지 않습니다. 외부 API/SDK가 예상과 다르면 실제 응답·예외를 기록합니다.

## AI 도구 간 이어받기

도구별 대화 기록은 서로 공유되지 않을 수 있습니다. 공통 기억은 저장소 파일과 Git 이력입니다.

```text
멈추는 도구: CURRENT_STATE.md만 최신화하고 종료
사람: 다른 AI 도구 또는 새 세션으로 이동
이어받는 도구: AGENTS.md + CURRENT_STATE.md + git status/diff + 최근 커밋 확인
```

`CURRENT_STATE.md`는 최신 상태와 최근 체크포인트 2~3개만 유지합니다. 오래된 로그는 `docs/archive/`로 옮깁니다. 원본 프로젝트의 상태판이 지나치게 길어져 찾기 어려워진 경험을 반영했습니다.

## 교차 리뷰

한 도구가 구현했다면 다른 도구는 먼저 **읽기 전용 리뷰**를 합니다. 특히 호스트 CAD 버전 호환, DWG 데이터 손실, Undo/트랜잭션, 개인정보·라이선스, 설치·업그레이드 경로를 점검합니다. 리뷰가 끝난 뒤 필요한 수정 범위를 정합니다.

## 배포 전 최소 확인

- 지원하기로 한 AutoCAD 제품/연도와 배포 패키지에서 실제 로드가 되는가?
- 신규 설치와 기존 버전 업그레이드가 되는가?
- 샘플 도면 복사본으로 작업·저장·재실행을 했는가?
- 명령 취소, 예외, Undo/Redo 뒤 도면이 일관적인가?
- 설치 파일·문서·로그에 키, 사용자 도면, 개인정보가 없는가?
- 이전 릴리스로 되돌리는 방법과 담당자가 정해졌는가?

출시/데모가 가까워지면 동시 사용, 느린 외부 서비스, 재시도, 로그 수집, 장애 메시지도 별도 점검합니다.
