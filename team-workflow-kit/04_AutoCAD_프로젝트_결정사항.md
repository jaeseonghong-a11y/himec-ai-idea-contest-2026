# 04. AutoCAD 플러그인 프로젝트에서 먼저 정할 것

이 문서는 기술 스택을 미리 확정하지 않습니다. 답을 `docs/PROJECT_BRIEF.md`와 `docs/DECISION_LOG.md`에 기록한 뒤 구현합니다.

## A. 제품과 사용자

1. 어떤 사용자가 AutoCAD에서 무엇을 더 빨리·정확하게 할 수 있어야 하나요?
2. 플러그인이 하는 일과 “그걸 포함하는 무언가”(웹·데스크톱·서버·파일 변환기 등)의 역할 경계는 무엇인가요?
3. 첫 데모의 최소 성공 경로는 무엇인가요? 예: 도면 열기 → 명령 실행 → 미리보기 → 사용자 확인 → 도면 저장.
4. 자동으로 도면을 바꾸나요, 제안을 보여주고 승인을 받나요?
5. 하지 않을 것(Non-goals)은 무엇인가요?

## B. 실행 환경과 호환성

- 대상은 **정식 AutoCAD**, AutoCAD LT, 다른 Autodesk 제품, 또는 호환 CAD 중 무엇인가요? 제품별 지원 API가 다를 수 있으므로 가정하지 않습니다.
- 지원 연도/업데이트, Windows 버전, CPU 아키텍처, 언어, 필수 .NET 런타임은 무엇인가요?
- 개발 방식은 .NET API, AutoLISP, ObjectARX, 외부 프로세스 연동 중 무엇이 요구사항과 맞나요?
- 설치·로딩 방식, 신뢰 경로, 보안 설정(`SECURELOAD` 등), 서명·라이선스 조건은 무엇인가요?
- 팀이 시험할 실제 AutoCAD 버전과 CI가 사용할 수 있는 SDK/참조 어셈블리는 무엇인가요?

Autodesk는 버전별 API와 보안 로드 조건을 문서화합니다. 실제 대상 버전의 공식 자료를 확인하세요: https://help.autodesk.com/cloudhelp/2026/ENU/AutoCAD-Customization/files/GUID-D54B0935-1638-4F97-8B37-1EC3635A1E71.htm

## C. 도면 데이터 안전성

- 단위(mm/inch 등), 좌표계(UCS/WCS), 축척, 블록·외부참조·레이어 처리 규칙은?
- 잠긴 레이어, 읽기 전용 도면, 선택 객체 없음, 손상된 도면, 여러 도면 동시 열기에서 어떻게 동작하나요?
- 명령 취소·예외 때 모든 변경이 롤백되나요? Undo/Redo는 하나의 사용자 동작으로 묶이나요?
- 원본 DWG를 덮어쓰나요? 백업·미리보기·확인 절차는?
- 샘플 도면에는 개인·고객·회사 정보가 없는가요?

## D. 플러그인 밖의 제품

- 서버나 AI가 필요한가요? 필요하다면 어떤 데이터만 보내고 무엇은 로컬에 남기나요?
- CAD 세션과 동반 앱 사이의 데이터 계약, 버전 호환, 오프라인 동작은?
- 로그인·결제·계정·업데이트·오류 보고는 첫 버전 범위인가요?
- 사용자가 플러그인을 제거하거나 이전 버전으로 되돌릴 수 있나요?

## E. 처음 만들 기능과 테스트

순수 계산을 AutoCAD API에서 분리해 단위 테스트할 수 있게 설계합니다. 첫 기능은 호스트에서 로드해 **실행·취소·Undo·저장·재실행**까지 확인합니다. 지원 버전이 여러 개라면 버전별 smoke test 표를 만듭니다. 직접 시험하지 못한 버전은 지원한다고 쓰지 않습니다.
