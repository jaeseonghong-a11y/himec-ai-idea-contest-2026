# 05. 복붙 프롬프트 모음

`[ ]`를 새 프로젝트 값으로 바꿉니다. 프롬프트는 Codex·Claude Code 등 어느 도구에도 사용할 수 있게 작성했습니다. **한 세션에서 팀원 둘이 같은 파일을 동시에 편집하지 않게** 담당 범위를 함께 알려주세요.

## 0. 프로젝트 초기화

```text
이 저장소의 AGENTS.md, CURRENT_STATE.md, docs/PROJECT_BRIEF.md,
docs/DECISION_LOG.md와 git status --short를 먼저 읽어.

우리는 [누구]를 위해 [무엇]을 만드는 새 프로젝트를 시작한다.
AutoCAD 플러그인과 [동반 제품의 역할: 미정 가능]이 포함된다.
이전 시간표 프로젝트와는 별개다. 그 프로젝트의 기능·스택·서비스 정책을 가져오지 마.

docs/PROJECT_BRIEF.md의 AutoCAD 관련 미정 항목을 확인하고
1) 지금 결정해야 할 것, 2) 실제로 검증할 것, 3) 첫 수직 기능,
4) GitHub 브랜치·PR 역할 분담을 제안해줘.
확인되지 않은 AutoCAD API·호환성은 지어내지 말고 미정으로 적어.
아직 제품 코드는 작성하지 마.
```

## 1. 첫 수직 기능

```text
AGENTS.md와 docs/PROJECT_BRIEF.md를 읽고, [첫 사용자 시나리오]를
입력 → 처리 → AutoCAD 결과 또는 화면 표시까지 가장 얇게 구현해줘.
먼저 실제 지원 CAD 버전·SDK·로드 방식이 확인됐는지 점검해.
순수 계산을 CAD host API와 분리하고 단위 테스트를 추가해.
실제 AutoCAD에서 로드·실행·취소·Undo·저장·재실행 중 무엇을
검증했는지 구분해 보고해. 기존 미커밋 작업은 보존해.
끝나면 CURRENT_STATE.md를 업데이트해.
```

## 2. 평소 작업 시작

```text
AGENTS.md, CURRENT_STATE.md, git status --short, git diff,
git log --oneline -5를 먼저 읽어.
다른 팀원/도구의 미커밋 변경을 보존하고, 이번 작업 [작업명]을 진행해.
완료 기준은 [기준]이고 변경 담당 경로는 [경로]야.
관련 검증을 실제로 실행하고 CURRENT_STATE.md를 갱신해.
커밋·푸시·배포 여부는 이번 요청에 명시된 범위만 따라.
```

## 3. 팀원에게 전달: 브랜치와 PR 만들기

```text
origin/main을 최신화하고 [이슈/기능]만 담당하는
[feat/기능명] 브랜치를 만들어줘.
변경 전에 다른 사람의 미커밋 작업이 없는지 확인해.
구현 후 프로젝트의 검증 명령을 실행하고,
본인 변경만 커밋·push해. main에는 직접 push하지 마.
PR을 열고 변경 내용, 실제 CAD 버전 테스트, 미검증 항목,
스크린샷 또는 안전한 샘플 도면을 설명에 적어줘.
PR URL과 브랜치명을 나에게 보내줘.
```

## 4. 팀원 PR을 내가 병합해 달라고 요청할 때 ★

```text
GitHub PR #[번호]를 main에 병합해줘. 이 요청은 해당 PR의
검토·필요한 충돌 해결·검증·병합을 승인한다. 배포는 승인하지 않는다.

순서:
1. 현재 git status와 미커밋 변경의 소유자를 확인해 보존해.
   더러운 작업 트리는 reset/stash하지 말고 별도 worktree에서 작업해.
2. fetch 후 PR의 작성자·base/head·최신 SHA·diff·리뷰·CI를 확인해.
3. 기존 기능과 새 기능의 의미상 충돌까지 검토하고, 실패한 검사를 고쳐.
4. 병합 충돌은 양쪽 의도를 읽어 해결해. 판단이 필요한 제품 결정은
   근거와 선택지를 보고해. 한쪽 코드를 통째로 버리지 마.
5. 프로젝트 자동 검증과 실제 CAD smoke test를 가능한 범위에서 해.
6. 팀의 branch protection·리뷰 요건을 지키고, 검토한 SHA와 같은
   상태인지 확인한 후 PR을 병합해. 관리자 우회나 force push는 하지 마.
7. main 최신 SHA, 검증 결과, 미검증 사항, CURRENT_STATE.md 변경을 알려줘.
```

## 5. 병합 없이 PR 리뷰만

```text
PR #[번호]를 읽기 전용으로 리뷰해줘. 코드 수정·병합·push하지 마.
기능 회귀, API 호환성, 도면 데이터 손상·Undo, 테스트 누락,
비밀정보, 설치·배포 영향 순서로 확인해.
각 문제는 파일·줄, 재현 조건, 위험, 권장 수정으로 적어줘.
충돌이 없더라도 의미상 충돌이 있는지 봐줘.
```

## 6. 도구 전환: 멈추는 도구

```text
여기서 코드 작업을 멈춰. CURRENT_STATE.md를 최신화해:
이번에 한 일, 바뀐 파일, 실제 실행한 명령과 결과,
남은 문제, 다른 팀원 변경과의 관계,
Recommended Next Step. 코드는 추가 수정하지 마.
```

## 7. 도구 전환: 이어받는 도구

```text
AGENTS.md, CURRENT_STATE.md, 현재 git status/diff와
최근 커밋을 먼저 읽어. 기존 구현을 되돌리지 말고
Recommended Next Step부터 이어서 작업해.
실제 코드가 문서와 다르면 코드 기준으로 조사하고 기록해.
완료 후 CURRENT_STATE.md를 갱신해.
```

## 8. 실패한 검사 또는 버그

```text
[증상과 재현 단계]가 발생해. 먼저 관련 Git 변경과
실제 예외·로그를 확인하고 최소 재현을 만들어 원인을 좁혀줘.
원인이 확인되기 전에는 우회 코드를 넣지 마.
수정 후 동일 재현과 회귀 테스트, 실제 AutoCAD에서 필요한
수동 검증을 실행해. 확인하지 못한 환경은 미검증으로 표시해.
```

## 9. 교차 리뷰

```text
현재 작업 브랜치의 diff를 다른 관점에서 리뷰해줘.
특히 AutoCAD 제품/버전 호환, 도면 수정 트랜잭션,
취소·Undo·저장 후 재열기, 개인정보·라이선스,
설치·업그레이드, 죽은 코드·중복 코드를 확인해.
지금은 읽기 전용 리뷰만 해.
```

## 10. 릴리스 준비

```text
이번 릴리스 후보 [버전/커밋]을 검증해줘.
지원 CAD 버전 매트릭스, CI, 실제 host smoke test,
설치·업그레이드·제거, 샘플 도면 안전성,
릴리스 노트와 롤백 절차를 확인해.
관찰한 사실과 미검증을 나눠 보고하고,
실제 배포는 요청된 범위에만 따라.
```

## 11. 상태 문서가 길어졌을 때

```text
CURRENT_STATE.md의 최신 상태와 최근 체크포인트 3개만 남기고
오래된 항목은 docs/archive/로 이동해. 삭제하지 마.
Recommended Next Step은 현재 코드·PR 상태와 대조해 갱신해.
코드는 수정하지 마.
```

## Git 명령 치트시트

```powershell
git status --short
git fetch origin --prune
git switch main
git pull --ff-only origin main
git switch -c feat/example
git push -u origin feat/example
gh pr list
gh pr view 123
gh pr diff 123
gh pr checks 123 --watch
```

`gh`는 GitHub CLI입니다. 설치하지 않았다면 같은 작업을 GitHub 웹 화면에서 할 수 있습니다.
