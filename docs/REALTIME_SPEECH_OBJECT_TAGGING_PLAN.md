# 실시간 음성 기반 객체 태그 v0.4 구현 계획

> 상태: **계획 확정 전용 문서** (2026-09-29). 이 문서는 코드 구현, 실제 마이크 송신, 실제 API 호출을 수행했다는 뜻이 아니다. 다음 담당자는 이 문서의 작업 단위를 하나만 선택해 작은 PR로 구현한다.

## 1. 이번 버전에서 만들 경험

사용자가 AutoCAD 팔레트에서 `실시간 전사 시작`을 누르고 외부 전사에 동의하면, 녹음 중인 음성이 짧은 단위로 화면에 나타난다. 발화에 `C1`, `B12`, `기둥`, `덕트`처럼 객체를 가리키는 말이 있으면 태그 목록에 **검토 전 제안**으로 추가한다.

- 도면 안에서 이름이 정확히 하나로 맞으면 그 객체를 **제안 연결**한다. 사용자가 목록에서 확인·수정·연결 해제할 수 있다.
- 여러 객체가 맞거나 아무 객체도 찾지 못하면 `선택 필요`로 남긴다. 사용자가 목록에서 후보를 고르거나 `도면에서 직접 선택`으로 연결한다.
- 녹음 중 직접 클릭해 붙인 태그는 지금처럼 즉시 로컬 목록에 기록한다.
- 어떤 경우에도 실시간 태그만으로 도면을 수정하지 않는다. 기존의 `지시 승인`과 실행 단계는 별개로 유지한다.

즉, “자동 태그”는 자동 **제안**과 로컬 연결까지이며, 사람이 확인하기 전에는 확정 태그나 도면 변경으로 취급하지 않는다.

## 3. 사용자 화면과 상태 흐름

```text
[로컬 녹음 시작]
       |
       +-- [실시간 전사 시작] -- 동의/키/마이크 확인 -- 실패 --> [로컬 녹음만 계속]
                                      |
                                      +-- 성공 --> [전사 중 · 외부 전송 표시]
                                                       |
             마이크 PCM -----> 실시간 전사 -----> 부분 문장(말하는 중)
                                                       |
                                                       +--> 확정 문장 --> 객체 언급 후보 --> 태그 검토 목록
                                                                                                  |
                                           정확히 1개 후보 --> 제안 연결(검토 필요) --+
                                           여러/0개 후보 --> 선택 필요 -----------+--> 사용자 확인/수정/직접 선택
                                                                                         |
                                                                                     확정 태그 목록
```

팔레트의 `02 녹음 객체 태그` 카드를 다음처럼 확장한다.

1. 상단에는 `실시간 전사 시작`, `실시간 전사 중지`와 상태 표시를 둔다. 상태는 `꺼짐`, `동의 필요`, `전사 중`, `연결 오류`, `로컬 녹음만` 중 하나여야 한다.
2. 전사 중에는 마지막 부분 문장을 한 줄로만 보인다. 부분 문장은 확정 기록이나 태그로 저장하지 않는다.
3. 확정 문장이 들어오면 목록에 시간, 발화 일부, 태그 이름, 상태, 연결 후보, 조작 버튼을 보인다.
4. 상태는 사람이 알아볼 수 있게 `직접 연결`, `제안 연결(확인 필요)`, `선택 필요`, `확정`으로 표기한다. 내부 상태명만 화면에 노출하지 않는다.
5. 각 줄에서 태그 이름 편집, 후보 변경, 도면에서 직접 선택, 연결 해제, 삭제를 할 수 있어야 한다. `확정`은 사용자가 누른 경우에만 된다.
6. 기존 `전사문에서 객체 찾기`와 일괄 파일 전사는 유지한다. 실시간 기능을 쓰지 않는 사용자는 기존 방식 그대로 작업할 수 있어야 한다.

## 4. 기술 설계

### 4.1 오디오와 실시간 전사

현재 `AudioRecorder`는 16 kHz WAV만 저장한다. 실시간 모드에서는 새 녹음을 **24 kHz, 16-bit, mono PCM**으로 캡처하고, 같은 PCM을 (a) 로컬 WAV 작성과 (b) 실시간 전사 전송에 동시에 사용한다. 장치가 이 형식을 열지 못하면 원인을 보여 주고 실시간 전사는 시작하지 않는다. 기존 16 kHz WAV 파일의 사후 일괄 전사 기능은 유지한다.

실시간 연결은 OpenAI의 전사 전용 세션으로 한정한다.

- 모델: `gpt-live-transcribe`
- 세션 성격: `type: transcription`
- 입력: 24 kHz PCM 오디오 조각
- 언어: 한국어(`ko`), 단 일반적인 CAD 용어만 포함한 짧은 안내문/키워드 사용
- 문장 진행: 부분 결과(delta)는 화면에만 표시하고, 완료 결과(completed)만 세션과 태그 후보에 반영
- 발화 마감: 이 모델에서는 서버 VAD에 의존하지 않는다. 클라이언트의 무음 감지 또는 사용자의 중지 시점에 오디오 버퍼를 명시적으로 commit한다.

OpenAI가 이 모델에 단어별 시간·화자 분리·신뢰도를 제공하지 않으므로, 화면의 시간은 오디오 프레임 누적값에 따른 **근사 시각**으로만 표시한다. 단어 단위로 정확하다고 주장하지 않는다.

### 4.2 로컬 객체 후보 찾기

실시간 전사 결과에서 먼저 기존 규칙과 같은 명시 식별자(`C1`, `B12` 등)와 일반 객체어(`기둥`, `덕트` 등)를 후보로 뽑는다. 다음 단계는 전부 로컬에서 수행한다.

1. 현재 도면의 블록명·속성·사용자 지정 태그·레이어를 읽어 `DrawingObjectIndex`를 만든다.
2. 명시 식별자가 한 객체와만 일치하면 `제안 연결(확인 필요)` 태그를 만든다.
3. 두 개 이상이면 후보 수와 목록을 표시하고 `선택 필요`로 만든다.
4. 일반 객체어·상대 위치 표현(예: `왼쪽 세 번째`)·일치 0개는 자동 연결하지 않는다. 사용자가 도면에서 직접 지정하거나 후보를 골라야 한다.
5. 사용자가 바꾼 태그나 연결은 다음 세션에도 로컬 JSON에서 유지한다. 도면 객체 자체에는 XData·속성·주석을 쓰지 않는다.

### 4.3 세션 데이터 계약

기존 `RecordingTagSession`을 호환성 있게 확장한다. 과거 세션을 열 때도 깨지면 안 된다.

| 새 필드(계획명) | 뜻 | 저장 위치 |
|---|---|---|
| `TranscriptTurnId` | 확정 전사 문장을 식별하는 값 | 로컬 세션 JSON |
| `ApproximateOffsetSeconds` | 오디오 프레임 기준 근사 시각 | 로컬 세션 JSON |
| `SuggestionStatus` | 직접 연결/제안 연결/선택 필요/확정 | 로컬 세션 JSON |
| `CandidateHandles` | 로컬에서 찾은 후보 객체 핸들 목록 | 로컬 세션 JSON |
| `ConfirmedByUserAt` | 사용자가 확정한 시각 | 로컬 세션 JSON |

API 키, 원시 PCM, 웹소켓 전문, 고객 도면 원문은 이 계약에 포함하지 않는다. 저장은 임시 파일에 쓴 뒤 교체하는 방식으로 하며, 비정상 종료 뒤 손상된 JSON을 만났을 때는 원본을 보존하고 사용자에게 복구 안내를 보여야 한다.

## 6. 완료 검증표

### 자동 검증 (실제 API 키 불필요)

- `dotnet run --project autocad-plugin/Himec.ChangeCore.Tests/Himec.ChangeCore.Tests.csproj`
  - 후보 상태, 중복 방지, 세션 역호환, 사용자의 확정/해제, 자동 연결 금지 규칙을 검사한다.
- `dotnet run --project autocad-plugin/Himec.PalettePreview/Himec.PalettePreview.csproj`
  - 새 상태 문구, 태그 목록, 오류 표시, 저장/재열기 경로를 검사한다.
- `dotnet build autocad-plugin/Himec.AutoCad2026/Himec.AutoCad2026.csproj -c Release -p:NoWarn=MSB3277`
  - AutoCAD 2026용 DLL 빌드 성공을 검사한다. 경고 억제는 기존 알려진 참조 경고를 숨길 뿐, 호스트 실행 검증을 대신하지 않는다.
- 가짜 전송기를 쓰는 테스트에서 동의 거절·키 없음·중지 후에는 어떤 PCM도 전송 메서드로 넘어가지 않는지 검사한다.

### 실제 수동 검증 (키와 마이크 권한이 있는 담당자만)

1. 고객 자료가 아닌 짧은 테스트 도면과 테스트 발화만 준비한다. AutoCAD 2026에서 preview DLL을 `NETLOAD`한다.
2. `실시간 전사 시작`을 눌렀을 때 동의창이 먼저 보이는지, 취소하면 네트워크 전송 없이 로컬 녹음만 되는지 확인한다.
3. 동의 후 `C1 기둥을 위로 30센티미터 옮기자`처럼 테스트 발화를 말한다. 부분 문장, 확정 문장, `C1` 제안 태그가 순서대로 보이는지 기록한다.
4. 후보가 둘 이상인 도면과 `왼쪽 세 번째 기둥` 발화에서는 자동 확정·도면 변경이 일어나지 않고 `선택 필요`가 되는지 확인한다.
5. 사용자 직접 선택, 이름 수정, 연결 해제, 삭제, 세션 재열기를 확인한다.
6. 이 과정은 태그 기능 검증이다. 실제 도면 이동과 UNDO는 기존 승인·실행 기능의 별도 테스트로 기록한다.

실제 OpenAI 요청이 한 번이라도 실행되면 PR과 `CURRENT_STATE.md`에는 테스트 날짜, 사용한 비민감 테스트 문장, 성공/오류 결과만 기록한다. API 키·오디오 파일·응답 전문은 기록하거나 올리지 않는다.

## 7. 이번 범위에서 하지 않는 일

- 사람 동의 없이 마이크를 자동 업로드하거나, 중단 뒤 백그라운드 재접속하기
- 화자 분리, 단어 단위의 정확한 타임코드, 실제 회의록 자동 확정이라고 표시하기
- 실시간 결과만으로 AutoCAD 객체를 이동·삭제·저장하기
- 도면 전체 객체 목록·핸들·레이어를 외부 모델의 프롬프트로 자동 보내기
- Anthropic·Gemini 실시간 전사 엔진을 동시에 구현하기. 다중 제공자 비교는 이 기능이 검증된 뒤 별도 작업으로 분리한다.
