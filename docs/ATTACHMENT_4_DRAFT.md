# 붙임 4 출품작 문안 초안 — 설계 변경 피드백 루프

> 이 파일은 공식 붙임 4 양식이 아니다. 공식 양식 `sources/official/SRC-002_submission_forms.docx`에 옮기기 전 내용 검토용이다. `[확인 필요]`와 `미검증` 표기를 지우지 말고 실제 확인 후 채운다. 작성일 2026-09-29. 분야: 설계·엔지니어링. 팀명·대표: [확인 필요].

## 1. 제안 제목과 한 줄 요약

**회의의 설계 변경 지시가 도면에서 사라지지 않도록: AI 기반 설계 변경 피드백 루프**

회의 발화를 AI가 변경 지시로 정리하고 도면 PDF에 근거와 함께 표시한다. 설계자가 승인한 변경만 관련 CAD 도면에 반영하며, 누락되기 쉬운 연관 도면과 재검토 항목을 보고한다. AI는 해석과 후보 제안을 돕고, 좌표 확정·변경 실행은 명시적 데이터와 사람 승인에 맡긴다.

## 2. 해결하려는 업무 문제

설계 검토 회의에서 “C1 기둥을 위로 500 mm 옮기자”라는 변경이 나왔다고 가정해 보자. 담당자는 회의록을 정리하고 A-101 평면을 수정한 뒤, A-301 단면과 관련 일람표를 다시 확인해야 한다. 기계·전기·소방 도면의 영향도 별도로 살펴야 한다. 지시의 출처가 흩어져 있거나 대상이 “여기”처럼 모호하면, 어느 도면을 수정하고 어느 도면을 검토만 해야 하는지가 사람의 기억에 의존한다.

이 문제 장면은 팀이 설정한 합성 사례이며, 하이멕 내부의 실제 오류율·작업 빈도·처리 시간을 확인한 것은 아니다. 하이멕 공개 자료는 기계·전기·통신·소방 엔지니어가 참여하는 DX 추진과 설계 산출물·업무 프로세스의 통합 관리를 소개한다(SRC-004). 따라서 변경 지시와 도면 검토의 연결을 설계·엔지니어링 업무의 제안 대상으로 삼았다. 하이멕 내부 시스템에 현재 어떤 기능이 있는지는 공개 자료만으로 판단할 수 없다.

## 3. 제안 흐름과 AI의 역할

1. **발화 수집:** 회의 대본 또는 향후 음성인식 결과를 입력한다. 데모는 합성 텍스트만 사용한다.
2. **변경 항목 추출:** LLM이 대상 도면·객체·행동·수치·발화 원문을 구조화한다. 불명확한 대상은 후보와 확인 질문으로 남긴다. 원문에 없는 수치나 좌표를 채워 넣지 않는다.
3. **도면 표시:** 출력 시 함께 만든 객체 대응표(사이드카)의 태그와 PDF 위치를 대조한다. 일치한 항목만 해당 위치에 주석을 달고, 나머지는 경고로 표시한다. 사이드카가 없는 실제 PDF에서 객체가 자동 식별된다고 주장하지 않는다.
4. **사람 승인:** 설계자가 원문과 주석을 확인해 승인·수정·기각한다. 승인자와 시각을 남긴다. 승인되지 않은 변경은 CAD에 반영하지 않는다.
5. **제한적 전파와 재검토:** 데모에서는 승인된 C1 이동 한 건을 합성 DXF 평면·단면 사본에만 반영한다. 전기 도면 등은 자동 수정이 아니라 영향 검토 대상으로 보고한다. 구조 안전성이나 덕트·배관 간섭 해소는 전문 검토 사항으로 남긴다.

AI가 필요한 곳은 자연어 발화의 의도·모호함 해석과 검토 설명이다. 객체의 정확한 좌표 매칭과 단순 이동, 필수 승인 확인은 규칙 기반으로 처리한다. 제공자 3종(OpenAI·Anthropic·Gemini)을 사용할 계획이지만, 실제 구현·시연에 사용한 모델과 결과는 최종 검증 후 기록한다. 저장된 예시 응답을 사용한 시연은 `시뮬레이션`으로 표시한다.

## 4. 차별점

범용 회의 요약은 “무슨 말이 나왔는가”에서 끝나고, 도면 오류 검사는 “현재 도면이 맞는가”를 따로 확인한다. 이 제안은 **발화 근거 → 도면 주석 → 사람 승인 → 관련 도면의 제한적 변경 → 미해결 검토 항목**을 하나의 추적 가능한 흐름으로 묶는다. 장기적으로는 2D CAD의 객체 관계를 경량 그래프로 표현해 변경의 영향 범위를 관리할 수 있다. 이는 BIM/Revit을 대체한다는 주장이 아니라, 2D 도면과 회의 중심의 업무에 단계적으로 붙일 수 있는 확장 방향이다. 현재는 개념 및 선택적 합성 시각화 단계다.

## 5. 구현 범위와 검증 상태

| 단계 | 제출용 실제 목표 | 현재 검증 상태(2026-09-29) |
|---|---|---|
| 합성 도면·대본·사이드카 | DXF/PDF 3장과 대본 5문장 | 팀원 #17 진행 대기 |
| AI 변경 추출·주석·승인 | 4개 후보, 그중 모호한 1개 경고, 검토 로그 | 팀원 #18 진행 대기; 실제 API 호출 미검증 |
| 승인된 CAD 변경 | C1 Y+500 mm를 합성 DXF 2장에 반영 | 계약 예시로 단위 테스트 5건 통과(PR #23); 팀원 입력과 통합 미검증 |
| 관계 그래프 | 사이드카 기반 합성 관계 시각화 | 선택 기능 #20, 미구현 |
| AutoCAD 내부 플러그인 | 녹음·검토·수동 대상 지정·승인 후 블록 이동 | 사용자 추가 요청에 따라 #25에서 첫 구현 중. 빌드와 실제 AutoCAD 동작을 구분해 최종 갱신 필요 |

데모에서 한 단계라도 실패하면 실패한 기능은 구현 완료라고 표기하지 않는다. 실제 고객 도면·회의록을 외부 API에 전송하지 않는다. 실무 도입 시에는 데이터 반출 정책, 모델 배포 방식, 승인 책임, 로그 보존 기간, 도면 버전·좌표 대응 정확도를 별도로 검토한다.

## 6. 하이멕 DX 방향과의 연결 가능성

하이멕 저자 공개 논문은 업무 프로세스(HDP), 데이터베이스(HDB), 툴킷(HDT)의 통합 방향을 설명한다(SRC-004). 본 제안은 변경 승인 절차를 표준 프로세스로 만들고, 발화·도면·검토 이력을 데이터로 축적하며, 검증된 CAD 도구 앞뒤를 연결할 수 있다는 *팀의 확장 해석*이다. 실제 하이멕 플랫폼의 API, 데이터 접근권한, 운영 범위는 공개되지 않아 현 시점에서 연동 가능하다고 단정하지 않는다.

## 7. 기대효과와 측정 방법

- 회의 변경 항목의 **누락 수**: 회의 원문에서 사람이 확정한 변경 목록과 최종 도면 반영 목록을 대조한다.
- 관련 도면의 **불일치 수**: 같은 태그의 위치·사양을 평면·단면·일람표에서 비교한다.
- **변경 반영 소요 시간**: 기존 회의 후 수동 정리 과정과 제안 흐름을 동일한 합성 과제에서 비교한다.
- **검토 가능성**: 각 변경에 발화 근거·승인자·승인 시각·수정 도면 목록이 남는지 확인한다.

현재 정량 개선율은 측정되지 않았다. 실제 하이멕 업무에서의 효과는 시범 적용과 비교 측정 후 제시해야 한다.

## 8. 단계별 적용 계획

1. **작은 시범:** 합성 또는 반출 승인된 도면으로 발화 구조화·주석·승인만 검증한다.
2. **제한적 자동화:** 태그와 객체 대응표가 있는 변경 유형 한두 개만 승인 후 반영하고, 사본 비교와 되돌리기를 검증한다.
3. **연관 도면 확대:** 분야별 검토 규칙과 도면 버전 관리를 추가한다. 실제 내부 시스템 연동은 권한·API 확인 후 결정한다.
4. **관계 기반 관리:** 2D 객체 관계를 경량 그래프로 표현하는 방향을 연구한다. Revit/3D 연결은 이번 출품의 구현 성과가 아니다.
