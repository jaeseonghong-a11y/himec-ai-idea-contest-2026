# 녹음 후 전사문이 보이지 않는 문제 — 2026-09-29

## 재현과 원인

- 사용자 동작: AutoCAD 팔레트에서 녹음 시작·중지 후 `녹음 전사(API 호출)` 클릭. 전사문 칸은 비어 있음.
- 확인: `%LOCALAPPDATA%/Himec/Recordings`에 WAV 3개가 생겼고, 각 파일은 16 kHz/모노/약 2.66–8.65초의 읽을 수 있는 WAV였다. 오디오 내용은 듣거나 외부에 전송하지 않았다. 비영(非零) 신호 에너지만 확인했으며 음성 품질 판정은 아니다.
- 확인: 현재 PowerShell 프로세스 및 사용자·기계 환경변수에 `OPENAI_API_KEY`가 설정되어 있지 않았다. **키 값은 읽거나 기록하지 않았다.** AutoCAD 프로세스의 별도 환경값은 직접 조회하지 않았다.
- 코드 경로: v0.1.2 전사 함수는 키가 없으면 API 호출 전에 예외를 낸다. 오류 문구를 팔레트 맨 아래 상태란에만 표시해 스크롤 없이 보기 어려웠다. 따라서 이번 현상의 가장 유력한 원인은 키 미설정 + 오류 가시성 부족이다. 실제 외부 API 요청이 실패했다는 근거는 없다.

## 수정

- 키 설정 여부를 팔레트에 표시하고, 키가 없을 때 전사 버튼을 누르면 화면 가림 입력창을 먼저 띄운다. 키는 실행 중 메모리에만 둔다. 이전에 녹음한 로컬 WAV를 선택해 다시 전사할 수도 있다.
- 상태 메시지를 최상단에 고정하고 전사 실패는 모달 오류창으로도 알린다. API 응답의 `text`가 비어 있으면 완료로 오인하지 않는다.
- 로컬 녹음 저장과 API 전사는 계속 분리한다. 외부 전송 전 확인은 유지한다.

## 검증 경계

- v0.2.1 소스 빌드·독립 팔레트 미리보기·사용자별 번들 설치 후 실제 AutoCAD 2026 팔레트 표시까지 통과. 새 팔레트에 `전사 키: 미설정`과 기존 WAV 선택 버튼이 보인다. 실제 키로 API 전사를 호출하지 않았으므로 전사문 생성 성공은 아직 미검증이다.
- 후속: 사용자가 자신의 키를 팔레트에서 입력하고 **시험용 음성**으로 1회 호출하여 HTTP 성공·전사문 표시를 확인한다. 키를 채팅/Git/화면 공유에 노출하지 않는다.
