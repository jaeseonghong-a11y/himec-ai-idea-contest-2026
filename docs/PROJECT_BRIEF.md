## 한 줄 정의

회의에서 나온 설계 변경 지시를 AI가 구조화하고 도면 PDF에 표시한다. 사람이 확인한 변경만 관련 CAD 도면에 반영하고, 일관성 검사와 재검토 지점을 보고한다.

## 문제와 사용자

대상 사용자는 설계·설비 도면 작성자와 검토자다. 건축 변경이 기계·전기·소방 도면에 영향을 미칠 때, 회의 발화와 수정된 도면 사이에 누락·불일치가 생길 수 있다. 이는 팀의 문제 가설이며 하이멕 내부 오류율·시간 절감 수치는 확인되지 않았다. 사례는 `C1 기둥 이동 → 관련 도면 갱신과 설비 영향 재검토`로 잡되, 덕트·배관 간섭을 실제로 자동 해결했다고 주장하지 않는다.

## 사람이 통제하는 흐름

1. 합성 회의 대본에서 변경 항목과 원문 근거를 추출한다. AI의 역할은 발화 해석, 모호한 대상 후보, 설명 문안이다.
2. 사이드카의 객체 태그를 이용해 합성 PDF에 확실한 위치를 주석으로 표시한다. 매칭되지 않으면 경고로 남긴다. PDF↔실제 DWG 자동 대응은 이번 데모에서 검증하지 않는다.
3. 검토자가 항목별 승인·기각한다. 승인 전에는 CAD 파일을 수정하지 않는다.
4. 승인된 `C1 Y+500 mm` 이동 한 건만 합성 DXF의 평면·단면에 반영하고, 간단한 일관성 검사 결과를 보고한다. 설비 도면의 영향은 검토 대상으로 표시하되 자동 수정 범위로 약속하지 않는다.

## 데모 범위와 제외

- 우선순위 1: 대본 → 구조화된 변경 항목 → 주석 PDF → 사람 승인까지 작동.
- 우선순위 2: 승인된 블록 이동 한 건 → 합성 DXF 2장 반영 → 보고서. 실제 도면 적용, DWG 직접 수정, 자동 간섭 해결은 제외.
- 여유가 있을 때: 경량 관계 그래프를 시각화한다. 그래프는 장기 비전을 보여주는 선택 산출물이며 핵심 데모의 필수 조건이 아니다.
- 실시간 녹음·STT, AutoCAD 플러그인, Revit/3D 연동, 고객 도면은 이번 구현 범위에서 제외한다.
- 팀원 4명 모두 각자 API 키 사용 가능하고 OpenAI·Anthropic·Google Gemini 세 제공자를 사용할 계획이다. 실제 사용할 모델·호출 순서·비용 상한은 미정이다. 키는 각자 로컬 환경에만 두고 Git 또는 팀 채팅에 올리지 않는다. 연결 전 예시 응답은 `시뮬레이션`으로 표시하며 실제 AI 추론으로 소개하지 않는다.
