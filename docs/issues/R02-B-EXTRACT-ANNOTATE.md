## 목표

합성 회의 대본에서 변경 지시를 구조화해 PDF에 표시하고, 사람이 승인·기각하는 경로를 구현한다. 담당: `archuni`, 브랜치: `work/archuni/r02` (팀장이 생성한 뒤 시작).

## 담당 파일

`prototype/extract/`, `prototype/annotate/`만 편집한다. 입력·출력 계약은 `prototype/CONTRACT.md`를 따른다.

## 완료 기준

- 5문장 대본에서 변경 후보 4건(명확 3, 모호 1)을 추출·표시한다. 정확한 건수보다 원문 근거와 모호함의 구분을 우선한다.
- `changes.json`에 실제 호출 모드 `live_api` 또는 `fixture_replay`, 제공자, 원문 인용, 상태를 기록한다. 저장 응답은 실시간 AI 결과라고 소개하지 않는다.
- OpenAI·Anthropic·Gemini 세 제공자 계획을 고려해 출력 형식은 하나로 통일한다. 시간이 부족하면 실제 연결은 한 제공자부터 검증하고 나머지는 미구현으로 명시한다.
- 사이드카에 명시된 PDF 좌표가 있을 때만 위치 확정 주석을 쓴다. 모호하거나 매칭 실패 시 경고로 표시한다. CLI로 검토자 승인/기각을 받아 `reviewer`, `reviewed_at`을 기록한다.
- API 키는 각자 로컬 환경에만 둔다. 실제 실행 명령, 사용 모델, 호출 날짜, 성공/실패, 미검증 경계를 PR에 적는다.
- `main`·공통 문서·다른 담당 디렉터리를 수정하지 않는다. PR을 열고 병합하지 않는다.
