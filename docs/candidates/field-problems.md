**FP-01 · 과거 유사 설계의 근거 재사용**

- 장면: 신규 프로젝트에서 유사 용도·규모의 과거 안을 참고하려 하는데, 어느 프로젝트의 어느 파일에 그 근거가 있는지 모른다.
- 현재 처리 방식(`분석`): 기억에 의존해 폴더를 뒤지거나, 해당 프로젝트를 했던 사람에게 물어본다.
- AI가 필요한 이유(`분석`): 파일명·폴더 규칙이 통일되지 않으면 키워드 검색이 실패한다. "지하주차장 급기 조건이 비슷한 사례"처럼 **의미로 묻는 질문**은 규칙 기반 검색으로 풀리지 않는다. 답에 원문 문단·파일·페이지를 함께 표시하면 S5·S6의 검증 요구를 만족한다.
- 근거 강도: S1·S2·S3가 주최사 논문에 직접 적힌 문제라 매우 강하다.
- **중복 위험**: 하이멕은 이 문제를 이미 HDB(Engineering Database)로 다루고 있다고 논문에 썼다. 현재 HDB의 검색이 어디까지 되는지는 `미검증`. 제안하려면 "HDB를 대체"가 아니라 "HDB 위의 의미 검색 계층"으로 위치를 잡아야 한다.
- 확인할 질문: HDB에 현재 의미 기반 검색이 있는가? 표준자료 외 프로젝트 산출물도 들어가 있는가?

- AI가 필요한 이유(`분석`): 점검 항목은 두 종류로 갈린다. (a) 레이어 명명, 필수 주석 존재, 범례 누락처럼 **규칙으로 잡히는 것** (b) "이 계통도와 평면도의 계통 번호가 서로 다른 것 같다"처럼 **문맥 판단이 필요한 것**. (a)는 AI가 아니라 규칙 엔진의 몫이고, AI는 (b)와 **지적 후보의 우선순위 정리**를 맡아야 한다. 이 구분을 제안서에 명시하면 `JUDGING_STRATEGY.md`가 경고한 "규칙 기반으로 충분한 일을 AI라고 포장" 감점을 피한다.
- 데모 가능성: 높음. 이슈 #9 결과(`docs/candidates/prototype-feasibility.md`)에서 팀원 PC의 `ezdxf` 1.4.3으로 DXF 레이어·객체 회수가 실측 확인됐다. 합성 도면으로 독립 재현 가능.
- 확인할 질문: 검토 체크리스트가 표준화되어 있는가(S3와 연결)? 검토 1건당 대상 도면 수는?

**FP-03 · 장비 사양 비교표 작성**

- 장면: 여러 제조사 카탈로그에서 용량·효율·소음·치수·전기사양을 뽑아 비교표를 만든다.
- 현재 처리 방식(`분석`): PDF를 열어 값을 옮겨 적고 단위를 맞춘다.

**FP-04 · 계산서 입력값 타당성 점검**

- 장면: 검증된 Excel 계산 도구에 조건값을 입력해 계산서를 만든다. 계산식은 검증됐지만 **입력값이 이 프로젝트에 맞는지**는 사람이 판단한다.
- 현재 처리 방식(`분석`): 엔지니어가 경험으로 입력값을 정하고, 검토자가 결과를 본다.
- AI가 필요한 이유(`분석`): 오류는 계산식이 아니라 **입력 조건**에서 난다. 과거 유사 프로젝트의 입력 조건 분포와 비교해 "이 값은 유사 사례 범위 밖"이라는 **예외 후보**를 띄우는 일은 규칙으로 고정하기 어렵고, 근거(어느 사례와 비교했는지)를 함께 낼 수 있다.
- 차별성이 높은 이유(`분석`): S4에 따라 하이멕은 **검증된 계산 도구를 이미 갖고 있다.** 그것을 대체하겠다는 제안은 현실성이 없고 신뢰도 낮다. 반대로 **기존 도구를 그대로 두고 앞단(입력 점검)만 붙이는** 제안은 S4·S5·S6을 모두 존중하면서 기존 DX 위에 얹히는 구조가 된다. `JUDGING_STRATEGY.md`가 요구한 "어떤 기존 계산·검토 도구의 앞뒤 작업을 연결하는가"에 직접 답한다.
- 확인할 질문: 계산 도구의 입력 조건이 파일로 남는가(비교 대상 데이터가 존재하는가)? 이 부분이 `미검증`이면 데모는 합성 데이터로 한다.

**FP-05 · 커미셔닝 시험기록 정리와 재시험 우선순위**

- 장면: 개별 성능 검증과 통합 연동 테스트에서 체크리스트·계측값·시험 기록이 쌓인다. 어떤 항목을 먼저 다시 봐야 하는지 정해야 한다.
- 현재 처리 방식(`분석`): 담당자가 기록을 모아 편차를 찾고 재시험 대상을 판단한다.
- AI가 필요한 이유(`분석`): 기록은 수치, 체크 표시, 자유 서술 메모가 섞여 있다. 수치 편차는 규칙으로 잡히지만 **메모에 적힌 단서**("2차측 밸브 임시 조치 후 측정")는 문맥 해석이 필요하다. AI는 수치 편차와 메모 단서를 엮어 **재시험 우선순위 초안**을 내고, 담당자가 확정한다.
- 차별성이 높은 이유(`분석`): 커미셔닝은 SRC-003에 적힌 하이멕의 **공식 서비스**인데 공모 예시(S8)에는 없다. 주최사 업무에는 있으나 예시로 주어지지 않은 영역이라, 창의성 25점에서 유리할 수 있다.
- 확인할 질문: 시험 기록이 디지털(엑셀·앱)인가 종이인가? 종이면 데모 입력 단계가 달라진다.

## 4. 사용자 시나리오

상위 3개 후보에 대해 "입력 → AI 처리 → 근거 있는 출력 → 사람 승인"을 한 문단으로 적는다. 등장인물은 **가상의 역할**이며 실제 하이멕 직원이 아니다(`팀 가정`).

**시나리오 A — FP-04 계산서 입력 점검**
설계 엔지니어가 신규 데이터센터 프로젝트의 냉수 배관 계산을 시작한다. 늘 쓰던 검증된 Excel 도구를 열기 전에, 이번 프로젝트의 입력 조건표를 도구에 붙여 넣는다. 도구는 과거 유사 규모·용도 프로젝트의 입력 조건과 비교해 "설계 외기온도는 유사 사례 12건 중 범위 밖(이 프로젝트 34℃ / 사례 범위 31.5~33℃), 근거: 프로젝트 P-2023-041 계산서 3쪽"처럼 **예외 후보 3건과 각각의 비교 대상**을 띄운다. 엔지니어는 각 항목을 보고 "이 현장은 옥상 실외기 배치라 의도한 값" 같은 사유를 적어 기각하거나, 값을 수정한다. 기각·수정 이력과 검토자 이름이 함께 저장된다. **AI는 계산을 하지 않는다.** 계산은 기존 검증 도구가 그대로 하고, AI는 그 앞단에서 확인할 것을 골라줄 뿐이다.

**시나리오 B — FP-05 커미셔닝 재시험 우선순위**
커미셔닝 엔지니어가 한 주 동안의 개별 성능 시험 기록을 올린다. 도구는 기준값 대비 편차가 큰 항목을 수치로 뽑고, 동시에 자유 서술 메모에서 "임시", "재확인 요", "우회" 같은 단서가 붙은 항목을 함께 묶어, **재시험 우선순위 초안**을 낸다. 각 항목에는 근거가 붙는다: 어떤 측정값이 기준의 몇 %를 벗어났는지, 어느 메모의 어느 문장 때문에 올렸는지. 엔지니어는 순위를 바꾸거나 항목을 빼고 확정한다. 확정된 목록이 다음 주 시험 계획이 되고, 통합 연동 테스트 단계에서 같은 항목이 다시 걸리면 이력이 연결된다.

**시나리오 C — FP-02 도면 누락·불일치 점검**
설계 검토자가 검토 대상 도면을 DXF로 내보내 올린다. 도구는 먼저 **AI 없이** 규칙 점검을 돌려 레이어 명명 위반·필수 주석 누락을 확정 오류로 표시한다. 그다음 AI가 계통도와 평면도의 계통 번호·장비 태그를 대조해 "불일치 의심" 후보를 근거(양쪽 도면의 해당 객체 위치)와 함께 낸다. 검토자는 확정 오류는 바로 수정 요청으로 보내고, 의심 후보는 하나씩 승인·기각한다. 기각된 패턴은 다음 검토에서 우선순위를 낮춘다. LLM 호출이 실패해도 규칙 점검 결과만으로 검토가 끝까지 돌아간다.

## 8. 충돌 가능성

- 변경 파일은 `docs/candidates/field-problems.md` 하나이고 **신규 생성**이다. `origin/main` 및 다른 팀원 브랜치와 파일 교집합이 없다.
- `docs/PROJECT_BRIEF.md`, `CURRENT_STATE.md`, `AGENTS.md`는 **건드리지 않았다.** `AGENTS.md`가 공통 문서 동시 편집을 금지하고, `CURRENT_STATE.md`는 팀장 AI가 갱신하기 때문이다.
- 이슈 #8(`docs/candidates/idea-comparison.md`, `ehgudwns18`)은 이 문서를 **입력으로 받는** 관계다. 파일은 겹치지 않지만, 이 문서의 후보 ID(FP-01~FP-07)를 이슈 #8이 인용하면 내용 의존이 생긴다. ID를 바꾸려면 두 담당자가 함께 정해야 한다.
- 이슈 #9(`docs/candidates/prototype-feasibility.md`, `kijun-0108`, PR #13 열림)의 3장 분야별 권장 경로와 이 문서의 후보는 서로 맞물린다. FP-04·FP-02는 그 문서의 경로 C(Python + `ezdxf`)에 대응한다. 상충 내용은 확인되지 않았다.
