# 결정 기록

> 중요한 선택과 번복을 짧게 기록한다. 새 결정이 이전 결정을 대체하면 이전 항목을 함께 표시한다.

## 2026-09-29 AutoCAD 플러그인 우선 구현과 배포 경계

- 상황: 사용자가 출품작의 중심 경험을 AutoCAD 안의 녹음·변경 대상 확인·최종 실행으로 다시 명확히 했다. Vercel은 필수가 아니라 업데이트가 쉬운 운영 방식의 예시였다.
- 결정: 기존 Python 합성 데모는 팀원 브랜치에서 계속 진행하고, 팀장 작업으로 AutoCAD 2026용 로컬 플러그인 v0를 우선 만든다(#25). AutoCAD 2024는 다른 .NET 대상이므로 별도 빌드/시험한다.
- 첫 범위: 녹음 버튼, 사용자가 선택한 전사 API 호출, 규칙 기반 이동량 추출, 모호할 때 수동 대상 선택, 승인 후 블록 한 건 이동. 자동 후보는 단일 줄의 기둥 세 번째만 *추천*하며 실행 대상을 확정하지 않는다. 여러 지시/도면 전파와 LLM 의미 해석은 후속이다.
- 배포: 플러그인 DLL은 PC에 설치·버전 갱신한다. 향후 AI 처리 API는 중앙에서 갱신할 수 있지만, 서버 배포만으로 로컬 DLL이 즉시 교체되지는 않는다. 보안 설정을 낮추거나 원격 코드를 자동 실행하지 않는다.
- 검증 경계: 빌드 성공은 AutoCAD 로드·녹음·도면 수정 성공과 별개. `docs/AUTOCAD_PLUGIN_ARCHITECTURE.md` 및 `autocad-plugin/README.md`를 따른다.

## 2026-09-29 출품 아이디어 및 최소 데모 확정

- 결정: `HIMEC_아이디어_평가_및_워크플로우.md`의 설계 변경 피드백 루프를 `설계·엔지니어링` 분야 단일 출품안으로 채택한다. 이전 FP-04/FP-02 우선순위는 후보 조사 당시의 권고로 남기고, 현재 제품 방향으로 사용하지 않는다.
- 최소 데모: 합성 대본의 변경 지시 구조화·PDF 주석·사람 승인 우선. 이후 승인된 블록 이동 한 건을 합성 DXF 2장에 반영하고 검사 결과를 보고한다. 관계 그래프는 선택 범위다.
- 이유: 회의 지시가 관련 설비 도면에 반영되는 피드백 루프가 하이멕의 설계·엔지니어링 맥락과 연결된다. 다만 회사 내부 문제 빈도와 구현 가능성은 검증된 사실이 아니다.
- AI 연결: 팀원 4명 모두 각자 API 키 사용 가능. OpenAI·Anthropic·Google Gemini 세 제공자를 사용할 계획이나 실제 모델·호출 순서·비용 상한은 미정. 키는 공유·커밋하지 않는다.
- 보류: 실제 DWG/PDF 객체 매핑·AutoCAD 연동. 검증 전까지 합성 DXF와 사이드카만 사용한다.
- 영향: Round 01의 아이디어 비교·후보 조사 작업은 참고 기록으로 보존하고, Round 02 구현 작업은 `prototype/CONTRACT.md`의 형식으로 분리한다.

## 2026-09-29 협업 기준선

- 상황: 여러 팀원이 각자의 AI 도구를 사용하면서 하루 안에 결과물을 통합해야 한다.
- 검토한 선택지: 공유 폴더 직접 편집 / 기능 브랜치와 PR 기반 통합
- 결정: `main`을 보호하고 작업별 브랜치, PR, 팀원 검토, squash merge를 사용한다.
- 근거: AI 도구 간 대화가 공유되지 않아 저장소 문서와 Git 이력이 공통 기억 역할을 해야 한다.
- 영향: 모든 작업자는 `AGENTS.md`와 `CURRENT_STATE.md`를 읽고, 본인 브랜치에서 작업한 뒤 PR을 연다.
- 다시 볼 조건: GitHub 요금제 또는 권한 때문에 보호 규칙을 적용할 수 없을 때 동등한 수동 검토 절차를 기록한다.

## 2026-09-29 공개 저장소와 팀장 전용 `main` 통합

- 상황: 개인 GitHub Free 계정의 비공개 저장소에서 보호 규칙 API가 403을 반환했다.
- 결정: 사용자의 명시적 지시에 따라 저장소를 공개로 전환하고 `main` 대상 Ruleset 24130976을 활성화했다.
- 설정: `main` 갱신·삭제·강제 push 제한, 선형 이력, squash PR 병합; 관리자 역할만 우회 가능. 세 팀원은 Write, 소유자만 Admin이다.
- 영향: 팀원은 `work/<사용자명>/rNN`에 push하고 PR을 연다. 팀장 AI는 PR 검토 후 병합한다. 공개 저장소의 모든 Git 이력이 외부에 보이므로 작성된 참가 서류와 비밀값은 저장소 밖에서 관리한다.
- 다시 볼 조건: 소유자 외에 관리자 권한을 부여하거나 저장소 공개 범위를 바꾸는 경우.
