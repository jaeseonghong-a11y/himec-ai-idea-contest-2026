# AutoCAD 2024 합성 도면 스모크 테스트

AutoCAD 2026용 절차는 `SMOKE_TEST.md`를 그대로 쓴다. 이 문서는 **2024 전용 빌드**에서만 달라지는
부분과 실제 실행 결과를 기록한다. 시험 도면 `three_columns_mm.dxf`는 2026과 같은 파일을 쓴다.

실제 프로젝트 도면을 쓰지 않는다. 합성 도면의 **사본**만 사용한다.

## 사전 조건

| 항목 | 값 |
|---|---|
| AutoCAD | 2024 (R24.3) |
| 번들 | `Himec.ChangeLoop2024.bundle` |
| 설치 경로 | `%APPDATA%\Autodesk\ApplicationPlugins\Himec.ChangeLoop2024.bundle` |
| 플러그인 DLL | `Himec.AutoCad2024.dll` (.NET Framework 4.8, x64) |

2026용 `Himec.ChangeLoop.bundle`이 함께 설치돼 있어도 된다. 두 번들은 폴더·DLL 이름·ProductCode가
달라 서로 영향을 주지 않는다. 설치는 `install-user-2024.ps1`을 쓰고, AutoCAD를 먼저 종료한다.

## 호스트 없이 확인한 것

아래는 AutoCAD를 실행하지 않고 빌드 산출물만으로 확인한 결과다. **기능 동작 검증이 아니다.**

| 확인 | 결과 | 방법 |
|---|---|---|
| 대상 프레임워크 | `.NETFramework,Version=v4.8` | 어셈블리 메타데이터 |
| 프로세서 아키텍처 | x64 (PE 머신 타입 0x8664) | PE 헤더 |
| 어셈블리 이름 | `Himec.AutoCad2024` | `AssemblyName.GetAssemblyName` |
| 명령 등록 | `HIMEC`, `HIMEC_PICK`, `HIMEC_SUGGEST`, `HIMEC_APPLY`, `HIMEC_TAG_PICK` | 메타데이터 문자열 |
| 매니페스트 | `SeriesMin`/`SeriesMax` 모두 `R24.3` | `PackageContents.xml` |
| 번들 구성 | 22개 파일, 필수 DLL 누락 없음 | `package-2024.ps1` 검사 |
| 설치 | 버전 `0.3.1.0`, DLL SHA-256이 빌드 산출물과 일치 | `install-user-2024.ps1` 출력 |

## 호스트 절차

1. AutoCAD 2024를 실행한다.
2. 합성 도면 **사본**을 `열기`로 연다. 현재 도면에 **삽입하지 않는다.** 삽입하면 기둥 3개가 외부 블록
   하나로 묶여 대상 선택이 되지 않는다.
3. 명령창에 `HIMEC`을 입력한다. 어두운 **HIMEC 설계 변경** 팔레트가 열려야 한다.
   보안 경고가 나오면 경로·버전을 직접 확인한다. `SECURELOAD`를 낮추지 않는다.
4. 전사문 칸에 `왼쪽에서 세번째 이 기둥을 위로 30CM위로 옮기자`를 넣고 `전사문에서 이동 지시 찾기`를
   누른다. X 0 / Y +300 mm가 나오는지 확인한다.
5. `'왼쪽 세 번째' 후보 찾기`를 눌러 후보가 추천되는지 확인한다. **추천은 확정이 아니다.**
6. `도면에서 대상 직접 선택`으로 오른쪽 끝 블록을 클릭해 핸들이 표시되는지 확인한다.
7. 녹음 객체 태그: 태그 이름 입력칸의 회색 안내문이 보이는지 확인한다. 2024는 .NET Framework라
   `PlaceholderText` 대신 Win32 큐 배너(`EM_SETCUEBANNER`)로 구현했다. `UiCompat.cs` 참고.
8. `태그 추가` → `선택 태그에 객체 지정`으로 객체를 연결하고, 파일을 다시 선택했을 때 태그가
   그대로 복원되는지 확인한다. 세션 파일은 `%LOCALAPPDATA%\Himec\Sessions`에 저장된다.
9. 여기까지 도면이 **수정되지 않았는지** 확인한다. 승인 전에는 도면이 바뀌면 안 된다.
10. 승인 후 이동과 `UNDO`는 **별도 시험**으로 분리해 기록한다.

### 관계도 연동

관계도 편집기의 코어(`editor/template.html`)를 node 로 불러와 위 JSON 을 그대로 먹였다.
확정 항목은 `resolveInstruction` 이 핸들 `8E` 로 기둥 `C@X1-Y2` 를 바로 찾았고(`by handle`),
미확정 항목은 검토 대기로 남았다. 사람이 도면에서 다시 찍는 단계가 없다.

이 시험의 관계도 그래프는 시험 도면과 같은 핸들·축 이름으로 합성한 것이다.
`build_graph_real.py` 로 실제 도면에서 만든 그래프로는 아직 확인하지 않았다.

### 남은 미검증

- 승인 후 도면 편집과 UNDO
- 레이어 포함 PC3 경로 (`HIMEC PDF (layers).pc3` 를 만들지 않아 기본 드라이버로 폴백)
- 실제 전사 API 호출 (키 없음)
- 실제 도면 그래프와의 연동

## 이 폴더의 시험 산출물

| 파일 | 내용 |
|---|---|
| `final_plug_in_test.dwg` | 시험에 쓴 도면. 합성 기둥 6개에 치수·중심선·축열을 더했다 |
| `final_plug_in_test.pdf` | 위 도면에서 내보낸 결과 |
| `final_plug_in_test.json` | 같은 내보내기가 만든 관계도용 지시 파일 |

세 파일 모두 합성 자료다. 실제 프로젝트 도면이나 회의 내용은 들어 있지 않다.

## 실패했을 때

어느 단계든 다르게 보이면 **다음 버튼을 누르지 말고** 화면과 명령창 메시지를 기록한다.
다음 정보를 함께 남긴다. API 키, 실제 녹음, 고객 도면은 첨부하지 않는다.

- AutoCAD 버전과 빌드 번호
- 번들 버전과 `Himec.AutoCad2024.dll`의 SHA-256
- 재현 단계와 명령창 전문
- 합성 시험 도면을 썼는지 여부

`HIMEC` 명령 자체가 인식되지 않으면 설치 경로에 번들이 있는지, AutoCAD를 재시작했는지,
매니페스트의 `SeriesMin`이 `R24.3`인지 먼저 확인한다.
