# Round 02 팀원 AI 시작 요청문

아래 코드블록을 각 팀원이 자신의 AI에 **수정 없이** 붙여넣는다. 로그인 계정에 따라 담당 브랜치와 이슈가 자동으로 달라진다.

```text
HIMEC AI 활용 아이디어 공모전 Round 02 작업을 시작해줘.

저장소: https://github.com/jaeseonghong-a11y/himec-ai-idea-contest-2026

먼저 내 GitHub 로그인 사용자명과 저장소 접근권한을 확인해. 저장소가 없다면 clone하고, 이미 있다면 기존 파일과 미커밋 변경을 보존해. origin을 fetch한 뒤 최신 origin/main의 AGENTS.md, START_HERE.md, BRANCH_ASSIGNMENTS.md, CURRENT_STATE.md, docs/PROJECT_BRIEF.md, prototype/CONTRACT.md를 읽어. 로컬의 오래된 문서보다 origin/main의 배정표를 우선해.

내 사용자명으로 배정된 work/<사용자명>/r02 브랜치와 열린 이슈(#17, #18, #20 중 하나)를 찾고, 원격 브랜치가 실제로 존재하는지 확인해. 계정·배정이 일치하지 않으면 브랜치를 임의로 만들지 말고 나에게 알려줘. 일치하면 팀장이 만든 원격 r02 브랜치에서만 작업해. main과 다른 팀원의 브랜치는 읽기 전용이며 수정·push·merge·rebase·reset·삭제하지 마.

담당 이슈의 완료 기준과 prototype/CONTRACT.md의 JSON 형식·담당 파일 경계를 따라 구현해. 합성 데이터만 사용하고 API 키·고객 도면·실제 회의록·개인정보는 커밋하지 마. 네 키는 네 로컬 환경에만 보관해. OpenAI·Anthropic·Gemini 세 제공자를 사용할 계획이지만 실제로 호출한 제공자·모델만 검증 완료라고 기록해. 저장된 예시 응답은 fixture_replay로 표시하고 실시간 AI 결과라고 말하지 마.

가능한 범위의 실행·테스트를 직접 확인해. 완료 후 네 담당 파일만 commit/push하고 base가 main인 PR을 열어. PR 설명에는 변경 파일, 실제 실행 명령·결과, API 호출 여부, 미검증 사항, 다른 담당자와 겹치는 부분, 다음 단계가 들어가야 해. PR을 직접 병합하거나 닫지 마. 새 브랜치를 만들지도 마.

마지막에는 로그인 계정, 담당 이슈, 사용 브랜치, commit SHA, PR URL, 검증 결과, 팀장 결정이 필요한 것만 간단히 보고해.
```
